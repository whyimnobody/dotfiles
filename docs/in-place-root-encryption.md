# In-place root encryption

This is a deferred runbook for converting the existing Arch Linux Btrfs root
partition to LUKS2 without reinstalling. It is a high-risk storage operation,
not a bootstrap step. Do not add it to `scripts/arch.sh` or run it unattended.

The result is encrypted root, not literally full-disk encryption:

- `/dev/nvme1n1p2` becomes a LUKS2 container holding the existing Btrfs
  filesystem and all its subvolumes, including `/`, `/home`, logs, snapshots,
  the package cache, and these dotfiles.
- The EFI system partition mounted at `/boot` remains unencrypted so
  systemd-boot can load the kernel and initramfs.
- `/dev/nvme0n1p1`, mounted at `/mnt/sora`, remains unencrypted. Encrypt it as
  a separate migration if its contents need protection.

## Recorded machine layout

These identifiers were recorded on 2026-08-31. Device names can change between
boots, so resolve and reverify them from the live ISO before doing anything.

| Purpose | Current identifier | Filesystem |
| --- | --- | --- |
| EFI `/boot` | UUID `F5C2-9D19` | FAT32 |
| Root partition | PARTUUID `3fb0fed3-5403-4413-9c3b-2dcdcff81729` | Btrfs |
| Root filesystem | UUID `23d57cef-1968-4687-8e83-ef654d9dcd29` | Btrfs |
| `/mnt/sora` | UUID `5fccfe16-81ae-4604-9fa3-c88d5c9e5a4a` | Btrfs |

The boot loader is systemd-boot. Both loader entries currently boot root by
the root partition's PARTUUID. The initramfs is generated by mkinitcpio using
the `udev` hook set, not `systemd`/`sd-encrypt`.

## Non-negotiable prerequisites

Do not begin until every item is true:

- There is a tested, restorable backup on a different physical device. Btrfs
  snapshots on the root disk are not a backup for this operation.
- Important repositories and irreplaceable files also exist off-machine.
- An up-to-date Arch installation ISO boots successfully on this hardware.
- The ISO has working keyboard input and can mount the root and EFI
  filesystems.
- The machine is on reliable power. A UPS is strongly preferred.
- There is enough time to let the entire roughly 2 TB partition complete
  without rushing or forcing a shutdown.
- The new LUKS passphrase and recovery material have a safe destination that
  is not on either internal disk.

`cryptsetup reencrypt` is designed to resume interrupted LUKS2 operations, but
that resilience is not a substitute for a backup. A command aimed at the wrong
partition can destroy unrelated data.

## Phase 1: record and test recovery information

Run these from the installed system and save the output off-machine:

```sh
lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,PARTUUID,UUID,MOUNTPOINTS
findmnt /
findmnt /boot
sudo btrfs filesystem show /
sudo btrfs filesystem usage /
sudo sfdisk --dump /dev/nvme1n1
```

Create and verify the real file-level backup before continuing. Boot the Arch
ISO once and confirm that the backup is readable from there.

## Phase 2: reserve space for the LUKS2 header

The in-place conversion needs unused space at the end of the plaintext
filesystem so its data can be shifted while the LUKS2 header is introduced.
The upstream cryptsetup example uses 32 MiB. Shrink Btrfs by exactly the same
amount that will later be passed to `--reduce-device-size`:

```sh
sudo btrfs filesystem resize -32M /
sudo btrfs filesystem usage /
```

This changes the filesystem size but does not change the GPT partition. Stop
if the resize fails. Do not substitute a partition-resizing command here.

After this step, shut down normally and boot the Arch ISO. The root filesystem
must not be mounted during the encryption initialization.

## Phase 3: initialize in-place LUKS2 encryption

From the live ISO, become root and verify the target using identifiers rather
than memory:

```sh
lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,PARTUUID,UUID,MOUNTPOINTS
blkid /dev/disk/by-partuuid/3fb0fed3-5403-4413-9c3b-2dcdcff81729
findmnt --source /dev/disk/by-partuuid/3fb0fed3-5403-4413-9c3b-2dcdcff81729
```

`findmnt` must produce no mount for the target. Resolve the symlink and compare
the size and old Btrfs UUID with the recorded layout. Then run the conversion:

```sh
cryptsetup reencrypt \
  --encrypt \
  --type luks2 \
  --reduce-device-size 32M \
  /dev/disk/by-partuuid/3fb0fed3-5403-4413-9c3b-2dcdcff81729
```

Read every prompt. Stop if the target or requested operation differs from the
plan. Do not reboot or interrupt the process merely because it is slow.

When it completes, inspect and open the new container:

```sh
cryptsetup luksDump /dev/disk/by-partuuid/3fb0fed3-5403-4413-9c3b-2dcdcff81729
cryptsetup open \
  /dev/disk/by-partuuid/3fb0fed3-5403-4413-9c3b-2dcdcff81729 \
  cryptroot
blkid /dev/mapper/cryptroot
```

The mapper must expose the original Btrfs UUID
`23d57cef-1968-4687-8e83-ef654d9dcd29`.

Back up the new LUKS header to removable media, not `/boot` or either internal
disk:

```sh
cryptsetup luksHeaderBackup \
  /dev/disk/by-partuuid/3fb0fed3-5403-4413-9c3b-2dcdcff81729 \
  --header-backup-file /path/on/removable-media/asura-root-luks2-header.img
```

Treat the header backup as sensitive recovery material.

## Phase 4: make the installed system unlock root during boot

Mount the root subvolume and EFI system partition:

```sh
mount -o subvol=@ /dev/mapper/cryptroot /mnt
mount --mkdir /dev/disk/by-uuid/F5C2-9D19 /mnt/boot
arch-chroot /mnt
```

In `/etc/mkinitcpio.conf`, add the traditional `encrypt` hook between `block`
and `filesystems`. Preserve all other hooks:

```sh
HOOKS=(base udev autodetect microcode modconf kms keyboard keymap consolefont block encrypt filesystems fsck)
```

Update both files under `/boot/loader/entries/`. Replace the current
`root=PARTUUID=...` argument while preserving the remaining arguments. The
resulting options line should be:

```text
options cryptdevice=PARTUUID=3fb0fed3-5403-4413-9c3b-2dcdcff81729:cryptroot root=/dev/mapper/cryptroot zswap.enabled=0 rootflags=subvol=@ rw rootfstype=btrfs
```

The entries are currently:

- `/boot/loader/entries/2025-05-17_13-30-06_linux.conf`
- `/boot/loader/entries/2025-05-17_13-30-06_linux-fallback.conf`

Regenerate both initramfs images and inspect the result:

```sh
mkinitcpio -P
lsinitcpio /boot/initramfs-linux.img | grep -E 'encrypt|cryptsetup'
```

The existing `/etc/fstab` entries use the inner Btrfs filesystem UUID, which
the conversion preserves, so they should not need changing. Verify this rather
than assuming it:

```sh
blkid /dev/mapper/cryptroot
grep -vE '^\s*(#|$)' /etc/fstab
```

Exit the chroot, unmount cleanly, and close the mapping:

```sh
exit
umount -R /mnt
cryptsetup close cryptroot
```

## Phase 5: first boot and verification

Keep the Arch ISO and removable recovery media connected for the first boot.
The initramfs should request the new passphrase before mounting root.

After login, verify every layer:

```sh
lsblk -f
findmnt /
cryptsetup status cryptroot
sudo btrfs filesystem usage /
systemctl --failed
```

Confirm that `/home`, snapshots, logs, the package cache, Tailscale, and tmux
restoration all behave normally. Keep the backup until the encrypted system
has survived multiple clean boots and a successful ISO-based recovery test.

## Remote-access consequence

A passphrase-protected root cannot start Tailscale or tmux until somebody
unlocks it at the machine after a reboot. Do the passphrase-only conversion
first. TPM2 or FIDO2 enrollment can be evaluated as a separate, reversible
follow-up after normal boot and recovery are proven. Automatic unlock improves
availability but changes the physical-threat model.

## Rollback

There is no casual undo button. LUKS2 supports in-place decryption through
`cryptsetup reencrypt --decrypt`, but it is another whole-device transformation
with the same backup, power, targeting, and recovery risks. Prefer restoring a
tested backup if the encrypted setup is not acceptable.
