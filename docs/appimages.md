# AppImage installation

This repository installs AppImages per user under
`${XDG_DATA_HOME:-$HOME/.local/share}/AppImage` and registers them with the
desktop launcher using a user-local `.desktop` file. It follows the
[AppImages on Arch guide](https://dev.to/sujit-shrc/install-appimages-on-arch-based-linux-lm2):
download the AppImage, make it executable, create a desktop entry, and refresh
the desktop database.

The installer is intentionally distribution-agnostic. It does not use
`pacman`, `sudo`, or a system-wide application directory.

## Prerequisites and limitations

The script requires `bash`, `curl`, `file`, `find`, `install`,
`mktemp`, `sed`, and `tr`. `desktop-file-validate` and
`update-desktop-database` are used when available. `sha256sum` is additionally
required when `--sha256` is supplied.

The script checks that the download is an ELF executable. That confirms the
file shape, not its identity or integrity. It does not discover the latest
release, verify a publisher signature, or infer a checksum from a download
page. Supply a trusted SHA-256 value with `--sha256` when one is available.

The script invokes the AppImage runtime with `--appimage-extract` to inspect
bundled icons. It does not launch the GUI during installation, but the
downloaded AppImage is still executable code; use an official or otherwise
trusted source. Launching the installed AppImage may have additional runtime
requirements such as FUSE support.

## Install an AppImage

From the repository root:

```sh
./scripts/appimage-install.sh \\
  --name "Example App" \\
  --url "https://example.com/releases/Example.AppImage"
```

For a release with a trusted checksum:

```sh
./scripts/appimage-install.sh \\
  --name "Example App" \\
  --url "https://example.com/releases/Example.AppImage" \\
  --sha256 "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

The script:

1. Downloads the AppImage to the user-local AppImage directory.
2. Sets mode `0755`.
3. Checks the ELF file type and, when supplied, verifies SHA-256.
4. Extracts a bundled icon when one is available.
5. Generates and validates a user-local desktop entry.
6. Refreshes the desktop database when `update-desktop-database` is available.

Preview all resolved paths and security-relevant inputs without changing
anything:

```sh
./scripts/appimage-install.sh \\
  --name "Example App" \\
  --url "https://example.com/releases/Example.AppImage" \\
  --dry-run
```

## Overwrite and update behavior

The installer refuses to replace an existing AppImage or desktop entry unless
`--force` is supplied. This protects an existing installation from an
accidental URL, filename, or metadata change.

Review the target first:

```sh
./scripts/appimage-install.sh \\
  --name "Example App" \\
  --url "https://example.com/releases/Example.AppImage" \\
  --dry-run
```

Then explicitly update it:

```sh
./scripts/appimage-install.sh \\
  --name "Example App" \\
  --url "https://example.com/releases/Example.AppImage" \\
  --force
```

`--force` replaces the AppImage, desktop entry, and any icon generated by the
new installation. It does not create a backup and does not remove
application-specific settings or caches. Keep the previous URL and checksum if
you need a rollback.

The installer does not query a vendor's latest-release API. For updates, get a
new official URL and checksum from the vendor's release/download page, review
them, then rerun with `--force`.

## Desktop metadata and launcher identity

The default AppImage filename and desktop ID are derived from a lowercase slug
of `--name`. Use explicit values when integrating an existing installation:

```sh
./scripts/appimage-install.sh \\
  --name "Example App" \\
  --filename "Example.AppImage" \\
  --desktop-id "Example.desktop" \\
  --url "https://example.com/releases/Example.AppImage"
```

`--desktop-id` controls the filename in the applications directory. Keeping
the existing ID preserves launcher pins and desktop-environment associations.
It must be a filename, not a path.

Optional metadata is emitted only when requested:

- `--comment` controls the launcher description.
- `--startup-wm-class` helps the desktop environment associate windows with
  the launcher.
- `--startup-notify` enables startup notification.
- `--categories` controls launcher grouping and defaults to `Utility;`.
- `--mime-types` registers URI or MIME handlers.

The installer does not silently invent these values, because replacing an
existing desktop entry should not discard application-specific integration.

## Icons and launch arguments

`--icon` accepts either a local icon path or an HTTP(S) URL. Icon URLs are
downloaded without separate checksum verification, so they must also be
trusted.

Without `--icon`, the script searches extracted AppImage icon directories for
PNG or SVG files, preferring common large icon sizes, then tries
`resources/icon.png`. If no icon is found, the desktop entry uses the
generic `application-x-executable` icon.

`--exec-args` is inserted literally into the desktop entry between the
quoted AppImage path and `%U`. It is not shell-evaluated by this script, but
desktop launchers interpret the resulting `Exec` field. Pass only trusted,
intentional arguments and avoid untrusted input or embedded newlines. No
arguments are added by default, including security-bypassing flags such as
`--no-sandbox`.

## Grok Bot example

Grok Bot's official Linux download page provides AppImage builds. This example
reproduces the existing launcher metadata without adding extra launch flags:

```sh
./scripts/appimage-install.sh \\
  --name "Grok Bot" \\
  --filename "Grok_Bot.AppImage" \\
  --desktop-id "Grok_Bot.desktop" \\
  --url "https://downloads.cursor.com/grokbot/stable/47a9d1df3a7d37aaa53d206ab2d1f9159a336223/linux/x64/Grok_Bot_0.61.0.AppImage" \\
  --comment "Grok Bot desktop agent" \\
  --startup-wm-class "grok-bot" \\
  --mime-types "x-scheme-handler/grokbot;x-scheme-handler/sand;" \\
  --categories "Development;"
```

See the [official Grok Bot download page](https://cursor.com/download/bot) and
[Linux setup instructions](https://docs.x.ai/grok-bot/get-started#linux).

## Verify an installation

Use the same values passed during installation:

```sh
data_home="${XDG_DATA_HOME:-$HOME/.local/share}"
app="$data_home/AppImage/Example.AppImage"
desktop="$data_home/applications/Example.desktop"

file "$app"
stat -c '%A %s %n' "$app" "$desktop"
sha256sum "$app"
sed -n '1,160p' "$desktop"
desktop-file-validate "$desktop"
```

`desktop-file-validate` is optional during installation but useful for
diagnosing launcher metadata. The application should also appear under its
`Name` in the desktop launcher.

## Uninstall

Use `--dry-run` or inspect the desktop entry before removing anything. Then
remove the exact user-local files:

```sh
data_home="${XDG_DATA_HOME:-$HOME/.local/share}"
rm -f \\
  "$data_home/AppImage/Example.AppImage" \\
  "$data_home/applications/Example.desktop" \\
  "$data_home/icons/example-app.png" \\
  "$data_home/icons/example-app.svg" \\
  "$data_home/icons/example-app.jpg"
update-desktop-database "$data_home/applications" 2>/dev/null || true
```

This does not remove application-specific settings or caches stored elsewhere
in the home directory.
